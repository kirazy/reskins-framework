Version: 0.2.1
Date: 2026-11-09
  Features:
    - Added setting "Show tier labels on belts", default on, for transport belts, underground belts, splitters, and loaders.
    - Added `tiers.assign_icons_with_tier_labels`, which assigns icon definitions from Artisanal Reskins: Sprite Utils with tier labels in batch to the prototypes of a given type.
    - Added `settings-utils.set_default_tier_color`, which may be imported and used during the settings stage to override the standard tier colors.
  Changes:
    - `tiers.icon_assignment_with_tier_labels` now accepts every form of an icon definition, with an optional `tier`, default 0, and returns `pictures` as an array of sprites.
    - The "Show tier labels on pipes" setting now also applies to heat pipes; `tiers.are_tier_labels_shown_for` now returns the applicable condition for `heat-pipe` prototypes.
    - `tiers.are_tier_labels_shown_for` now returns `false` for `"technology"`.
  Bugfixes:
    - Fixed that tier labels could be added to technology icons under some circumstances.

Version: 0.2.0
Date: 2026-11-01
  Features:
    - Updated for Factorio 2.1
    - Added setting "Show tier labels in world", default off.
    - Added `tiers.icon_assignment_with_tier_labels`, which is the preferred way to package an icon with tier labels for assignment and manages compliance with the current user settings and complexities around the pictures field for in-world icons.
    - Added `tiers.tier_label_group`, the icon composition group for tier labels.
    - Added support for icon compositions from Artisanal Reskins: Sprite Utils.
    - Added `api/validation` with preconfigured validators for types used by the framework.
  Changes:
    - `tiers` functions now validate parameters, and will throw on invalid inputs with descriptive messages.
    - `tiers.add_tier_labels_to_named_prototype` requires the named prototype to exist.
    - Removed `get_deferrable_icon_for_prototype_with_added_tier_labels`; use `tiers.icon_assignment_with_tier_labels` instead and assign the result.
